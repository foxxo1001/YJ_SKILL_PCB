# 架构

宿主读取共享 Skill，再调用 ehe CLI。Python 进程负责执行、留存和恢复。
领域计算器、EDA 适配器和知识检索输出结构化证据。独立 Gate 接收已绑定的
输入哈希和执行证据。用户通过 CLI 查看整改记录和复验结果。

## M0 风险登记

| 风险 | 识别与处置 |
|---|---|
| 工具安装与实际可执行能力不一致 | 分别记录安装发现、版本探测、实际原生检查 |
| 未变更的输入反复执行 | 使用内容指纹和有界重试 |
| 报告冒充实测 | 区分派生、工具、文档和实测证据 |
| 用户原始工程被修改 | 原生工具使用隔离的只读检查工作目录 |
| 评测答案泄漏 | 知识库只接纳可见分区，评测端另持隐藏集 |
| 数据来源不明 | 记录文件哈希、修订、可定位来源和授权 |
| 真实硬件和测量工况缺失 | L5 保留 not_run |

## 状态与证据边界

Runtime 以受约束的内置检查任务作为 DAG 节点。外部 EDA CLI 前先提交任务尝试，任务完成后再提交结果和证据。SQLite 在单事务中保存状态与事件，JSON 文件为可重建视图。项目进程锁限制并发操作。恢复时会记录中断尝试，并按预算重试只读任务。

原生 Gate 重新读取报告，将规则列表、严重度、退出状态、工具版本、原始证据哈希和输入快照对照。派生模型由 Gate 重算。已命名的物理 Gate 需要独立的原始测量和工况。放行状态由 EvalOps 根据固定答案、候选输入、差异、版本和人工验收条件决定。

工作副本提交以文件哈希和 diff 形成审批 ID。批准后先构建暂存目录，再原子发布并保留收据。进程在发布后中断时使用相同收据复验。知识库按来源授权和项目分组收录，评测方独立存放隐藏输入和答卷，仅共享隔离指纹。
