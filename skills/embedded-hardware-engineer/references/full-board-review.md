# 完整审查要求

先确认待审原理图、PCB 和适用工况。多套同名或不同版本并存时按项目清单选定正确的一套。使用报告的输入哈希与文件路径定位当前版本。给用户的首次结果按下表逐项写结论、证据位置和重要缺项，优先追问最能改变结论的资料。

| 审查项 | 证据与应答 |
|---|---|
| 原理图与 PCB | 实际 ERC/DRC、一致性检查、版本及对象。关键项还要逐网核对电源、引脚、保护和设计规则 |
| EMI 与回流 | 按电流方向追踪功放、电机开关、输入旁路和外接线束的实际路径，核对信号跨缝、换层与近端返回。把网名、层和局部位置写进报告。结合叠层、原生铜区及工况判断 |
| 板框和装配 | 从 Edge.Cuts 报板框标称尺寸。装配另外核对器件高度、固定孔/螺柱、插头插入和拔出路径、线束与壳体。列出 XY/Z 坐标基准及最小余量 |
| 电源、温升与容差 | 从实用工况找启动、负载阶跃、堵转、热环境和器件偏差。记录典型/最坏参数、来源、计算值、预算和余量。引脚掉压须区分电池、线束或板内路径 |
| 上板验证 | 给指标、测点、供电/载荷/温度条件、仪器或基准和通过阈值。缺实测时保留验证计划和待确认结论 |

涉及模拟、数字高速或开关电源时，再补采样建立、走线边沿、去耦和故障保护。实际板上无对应模块时可给出不适用依据。依赖外壳、层叠、线束或实测的数据缺失时，在覆盖表中写出缺失对象。

`review full` 给出逐项机器结果。把 `not_run` 或 `inconclusive` 转成读者能理解的缺项及下一步。`pass` 需注明证据级别，原生布局尺寸、包络估算和实物装配各有独立结论。模型 `not_applicable` 只保存项目声明，复核声明和板上证据后再采用。原生检查通过与实物验收分别报告。

做外部型号或器件参数判断时引用适用手册版本与条件。审查中创建的模型先单独保存并校对来源与单位，采用 `review full --model` 复算。
