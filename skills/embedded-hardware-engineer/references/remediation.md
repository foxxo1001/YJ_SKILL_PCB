# 整改与复验

遇到一个已知问题，先绑定当前修订和实际对象。遇到症状线索，列出能解释症状的少数假设，并先做能排除最多原因的观察。优先使用已有原理图、原生几何、手册和波形，缺少证据时写出成功判定逻辑。

| 字段 | 给用户的内容 |
|---|---|
| 位置 | 页码、位号、引脚、网、层、坐标或测试记录时间。优先给能定位的组合 |
| 机理 | 证据、成立条件、超限值与余量。把待证原因和已确认问题分开 |
| 改法 | 网络如何改、选哪个工作范围、器件搬到何处、走线如何经过参考面。量值应由设计、手册或计算支持 |
| 影响 | 受影响供电、布局、EMI、热、精度、时间与机械边界，列下一轮回归项 |
| 复验 | 复跑的 ERC/DRC 或计算，测量点、输入工况、阈值与旧版本的比较方式 |

可以优先给两条低成本方案并说明适用条件与取舍。确认目标是解决根因，例如先判断本地电源实际掉压，还是共享返回路径把局部参考抬高。已有波形不足时，先说明电源脚与 MCU 局部地、复位脚及负载电流应如何按同一事件对照。

检查阶段记录提案。得到授权后使用工作副本，保留原始版本和差异。规则类故障从原始报告提取位置，验证建议改动后受影响方向、网络和相邻布局。整改完成状态以重新运行的规则、计算或测量证据为准。
